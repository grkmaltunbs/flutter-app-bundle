What Claude does — the step's own spec

Description

The host spawns claude -p --input-format stream-json --output-format stream-json --include-partial-messages --replay-user-messages --permission-prompt-tool stdio --permission-mode default --session-id <uuid> in the project folder, with the shell's PATH (the hooks need dart). It writes user messages to stdin and reads one JSON object per line from stdout: system/init, stream_event deltas, assistant content, user tool results, control_request (a permission or an AskUserQuestion), result, rate_limit_event.

The protocol parser is pure Dart in kit/lib/src/bridge.dart — the phone will render the same transcript from the relay. The process runner is app/lib/src/host/bridge_session.dart, beside remote_control.dart, and the transcript is a Deck tab on the host: messages, compact tool rows, a composer, Start / Stop.

A control_request must be answered or the session hangs on it, so the Deck renders an ask card on the Mac from this step: Allow / Deny for a permission, the options for a question. "This session", "Always" and the phone come in asks.

The protocol is what Anthropic's Agent SDK speaks to the CLI; it is not a documented CLI contract. Proven on Claude Code 2.1.251 on 2026-08-30 (the table in app/DESIGN.md). The host records the CLI version it started and says so on the Session tab.

Acceptance

  • From the Mac window: Start → type /plan-status → the answer streams into the Deck; a Bash permission renders as an ask card; Allow lets it run, Deny shows the refusal in the transcript.
  • Stop ends the process; a host restart finds the session by id and offers Resume (--resume).
  • kit/test/bridge_test.dart covers the parser on captured lines; app/test/bridge_session_test.dart drives the runner with a fake process; a live test spawns the real claude only under KIT_LIVE=1.
